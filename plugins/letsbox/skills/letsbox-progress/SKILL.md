# LetsBox 進捗確認

## 目的

「いまのリサーチどうなってる？」「終わった？結果は？」に答えるスキルです。**状況確認のために新しい作業を始めてはいけません。**

## ルール

- 使ってよいのは、プラグインが登録済みのMCPサーバー「letsbox」のツールだけです。
- 進捗確認で `start_campaign` / `start_restock` を呼ぶことは禁止（新規作成は利用者の明確な依頼があるときだけ）。
- 途中で止まって見えても、勝手にキャンセルしたり作り直したりしない。キャンセルは利用者の明確な依頼があるときだけ `cancel_campaign` を呼ぶ。
- 利用者への報告は件数と状態を短くまとめ、内部ステータス名の羅列ではなく言葉で説明する。

## 対象の特定

1. **在庫戻し（Restock）**: `get_active_restock_campaign` はIDなしで実行中のものを返せる。まずこれを確認。
2. **リサーチ**: campaign IDが必要。このスレッドや直前の会話に出ていればそれを使う。見つからなければ「開始時に表示されたcampaign ID（英数字のID）を教えてください。開始したスレッドの最後の方に書いてあります」と優しく案内する。IDを推測してはいけない。

## 手順

1. `get_campaign` で状態を取得し、次の観点で報告する:
   - 全体: 実行中 / 判定待ち / 完了 / 失敗・保留 のどれか
   - 件数: 対象アイテム数、選定済み・見送り・確認待ちの内訳
   - 判定待ち（`waiting_for_judgement`）の場合: 「AI判定の続きが必要です。このスレッドで続けますか？」と確認し、OKなら claim_judgement → submit_judgement のループを再開する（並列判定が可能なホストではsubagentで並列に）
2. 詰まって見える場合は `get_campaign_events` で直近のイベントを確認する。30分以上変化がなくイベントにも動きがなければ、原因を推測せずcampaign IDと直近イベントをそのまま報告する。
3. 完了している場合は `get_report` を呼び、結果の要点（対象件数、利益が見込める件数、保留の理由、価格・在庫の更新件数）を短くまとめる。細部は `list_items` / `get_item` で必要な分だけ確認する。
4. ステータスが終端（完了・失敗・キャンセル・保留）になるまで、そのcampaignを「失敗した」と報告しない。
