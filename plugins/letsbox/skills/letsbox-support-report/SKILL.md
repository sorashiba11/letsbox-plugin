# LetsBox 不具合報告の作成

## 目的

「なんかおかしい」を、サポートが一読で状況把握できる報告文に変えるスキルです。利用者に技術的な質問を浴びせずに、集められる情報はツールで集めます。

## ルール

- 使ってよいのは、プラグインが登録済みのMCPサーバー「letsbox」のツールだけです。
- 報告文に秘密情報を入れない: SerpApiキー・パスワード・トークンは絶対に含めない（キーは「登録済み（下4桁 ××××）」のような表現まで）。
- ツール自体が失敗する状態でも、その失敗内容こそが報告材料。エラーをそのまま記録して報告文に含める。

## 手順

1. まず利用者に一言だけ聞く:「どの操作で、どんな症状が出ましたか？（例: リサーチを頼んだらエラーになった）」
2. 情報収集（失敗したらその旨をメモして続行）:
   - `get_connection_status` — アカウント、権限、認証情報の状態、サービスのバージョン
   - 対象のcampaign IDが分かる場合: `get_campaign` と `get_campaign_events`（直近のイベントを数件）
3. 次の形式で報告文を作り、コードブロックで提示する:

   ```text
   【LetsBox 不具合報告】
   日時: （いまの日時・タイムゾーン付き）
   アカウント: （メールアドレス / 会社名）
   症状: （利用者の言葉での説明＋実際のエラーメッセージがあれば原文）
   発生した操作: （何をしようとしたか）
   接続状態: （get_connection_status の要点。バージョン、権限の過不足、認証情報の登録状態）
   対象campaign: （IDと状態。無ければ「なし」）
   直近の出来事: （events の要点。無ければ「取得不可: 理由」）
   ```

4. 「この内容をLetsBoxサポートへ送ってください」と案内する。修正の見込みや原因の断定はしない（それはサポート側の仕事）。
5. その場で直せる定型問題（権限不足・認証情報未登録・ツールが見えない）だった場合は、報告文と併せて該当スキル（letsbox-connection-check / letsbox-setup）での復旧も提案する。
